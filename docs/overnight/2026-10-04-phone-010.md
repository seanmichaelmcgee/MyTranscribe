# Phone recording 010: local dictation iteration

## Result and build change

The 60.720-second phone recording contains the fictional examples 00, 06 and 10,
with spoken headings. The existing Whisper application recognizes the short
HGB/eGFR result correctly when processing the complete recording. Removing the
headings from its output for scoring gives 4.4% written word error before the
change and **3.5% after**, with target-term recall increasing from 16/17 to 17/17.
This is one recording, not three independent clinical observations.

The only production change is an exact, whole-word correction:
`dysthyatokinesia => dysdiadochokinesia`. The user confirmed reading the supplied
script, which establishes the intended spelling. The observed non-word recurred
across Whisper controls. This is a calibrated text correction, not a change to
model weights or a claim of improved acoustic recognition. The general corrector's
thresholds and real-word protections are unchanged. No HGV/HCV-to-HGB rule was added.

Fresh controls under the same updated source explicitly select the frozen old
correction file or the new bundled file. Across the **30 earlier voice clips**,
both retain **4.7% overall / 3.1% medical error**, the same 94.7% term recall,
30/30 formatting checks and 30/30 numbering checks. The new sample is calibration
material; an independent pronunciation example is needed to validate this rule.

WER can exceed 100% because insertions count. These are separate replays of cropped

The isolated result emits `Dr. Patel, HbA1c 7.4%, eGFR 52.` instead of the actual
instruction. Those values occur in the bundled style example. The full recording
provides surrounding speech and does not show this result-snippet failure.
Its four remaining word errors include a small insertion in the letter and
differences such as `change from prior exam` against the intended examination
sentence. We preserve the user's unchanged script: no reference was rewritten
from either engine's output. Direct listening was unavailable, so possible reading
variations have not been independently resolved.

## Experiments and rejected changes

Six fingerprinted Whisper controls tested 20/30-second cuts, no prompt, no
postprocessing, no topic terms and greedy search. Thirty-second cuts improve the
letter from one word error to none. Removing cleanup, topic terms or beam search
does not solve the isolated short result. Removing the example prompt prevents
its fabricated values but leaves abbreviation and wording errors.

Seven compact prompt presets were compared on both short sections: the original,
empty, minimal, assessment, broad existing results vocabulary, results vocabulary
with HGB/Hb, and existing examination vocabulary. None recovered all short-result
words or the neurological spelling. Manual topic presets are calibration controls,
not evidence of automatic topic detection. Another seven controls tested timestamp
decoding, VAD bypass, VAD bypass with a minimal prompt, 600-ms speech padding, and
the dedicated hotword channel with the two broad vocabulary lists. They did not
repair the two errors. Wider VAD padding and bypass did not explain this case.

A predeclared five-second minimal-style policy preserved prior transcript context
and topic terms and required no extra inference. It reduced phone-section WER
from 10.6% to 7.1%, but **worsened the prior corpus from 4.7% to 5.8% overall and
3.1% to 7.1% medical error**. Term recall fell from 94.7% to 90.4%. It was rejected;
no automatic short/long prompt switch was added to the app.

## MedASR comparison

The existing float32 model was tested with greedy decoding and the prior balanced
beam-32 LM and weaker beam-8 LM settings on the same isolated waveforms, at
20-second cuts. All three score 10.6% written WER and 5.9% medical error before
the Whisper correction. The two LM runs reuse verified acoustic arrays and measure
decoder work only. Neither establishes a new latency improvement or accuracy gain
on this recording. Full 30-second continuous and uncached paced runs were also made.

MedASR restores the neurological term through the existing spelling pipeline but
hears HCV for HGB. It emits age placeholders and bracketed headings in the letter;
these cannot be repaired by guessing the missing clinical value. The 30-second
paced version scores 13.3% written WER and misses one paragraph-count check,
compared with Whisper's 9.7% after the spelling rule. Whisper remains the product.
The shorter MedASR processing time does not compensate for these content errors.

## Corpus, bounds and validation

The original AAC/M4A is 44.1 kHz mono. Its byte-identical local copy has SHA-256
`e1f367cc65b6b83b0a1c4070454c7ad2a5b89c921067d815cdee315097a9726f`.
The unchanged-format importer makes one 16 kHz mono PCM copy without added gain,
denoising or trimming. Normalized RMS is 0.1113 and peak 0.9832, with no samples
counted as clipped. These values describe this phone file, not quiet/whispered
microphone sensitivity or the phone's upstream processing.

Spoken headings were located in a separate timestamp diagnostic. Fixed section
ranges are 5.30–8.18 s, 9.95–17.63 s and 19.34–60.7201875 s. Cropping removes
headings; it retains the letter's trailing silence. Both engines receive the same
PCM ranges. The canonical sample-packet hash is
`7e2d7481cd0ca79a3210ebe1176d60a924a26c31b50f44bcdb95b99676ce9cfb`.
Names are excluded by the historical scorer; medical eponyms remain scored.
Samples 09, 12 and 13 were not used. Continuous-output scoring removes only the
three recognized headings and has no per-section clocks or extra independent samples.

All originals, crops, transcripts, manifests, controls and telemetry remain ignored
under `results_1060/phone_010_20261004`. Each phase retains its actual source and
model fingerprints. The runner owns the existing exclusive GPU lock, executes
one child at a time, and uses the existing owned-process-tree cleanup with
300-second child and 30-minute phase limits. No package or model was installed.
The idle application was closed during GPU trials and restored after completion.

**451 unit tests passed in 30.49 seconds using headless Qt.** Native Windows
clipboard access remains unavailable in this session; this does not validate live
copy/paste or the phone's microphone routing. Spelling thresholds were not weakened.
The complete recording and all prior clips were replayed under fresh matched
correction controls; original-source results were finalized before editing.
Every raw and cleaned transcript in the prior corpus is unchanged by the new
rule. Across the completed phases, sampled whole-card VRAM peaked at 4,166 MiB
and temperature at 68 C; no thermal stop occurred. The final paced phase peaked
at 3,302 MiB / 54 C. Source fingerprints include the actual changed correction
file; the recorded Git revision alone predates the later commit.

An independent agent reviewed the prompt-copy diagnosis and scoring limitations.
A second agent was given only the audio, with no script or local transcript, to
attempt blind remote transcription. Its audio input was unsupported: it received
only a path and produced no transcript. There is no remote audio-transcription tool
or API key configured in this session. An authenticated
[file-transcription service](https://developers.openai.com/api/docs/guides/speech-to-text)
can provide that third baseline later; no remote transcript or listening review is
claimed here. The user explicitly authorized the attempt for this fictional audio.

The next useful samples are repeated independent short results and a new sentence
using the neurological term, followed by paired normal/whispered audio at a fixed
phone position. Short-result prompt copying needs a separate general solution;
the rejected duration policy should not be enabled simply to improve this file's score.
