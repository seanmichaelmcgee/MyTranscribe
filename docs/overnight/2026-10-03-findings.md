# Overnight findings 2026-10-03

## TL;DR (5 lines max)
1. **It runs on the GTX 1660 Ti**: preflight GO; large-v3-turbo on CUDA at **RTF 0.06** (a 30 s chunk in ~1.7 s), ~2 GB VRAM, peak 71 °C. 8 h, 7 cycles, 33 tasks: everything passed except 4 clipboard unit tests (environment) and the last `long` (cut off by the deadline).
2. Six 60-minute real-time dictations: never fell behind (max queue 1), Stop returns in 3 ms, final text in ~1.5 s, memory flat (~550 MB). 1,200 start/stop cycles, unplug and OOM fault injection, and 120 real-window hotkey cycles (worst UI stall 85 ms) all passed.
3. Vocabulary pipeline (topics+fix) vs none: **WER 7.6 % to 5.4 %, medical-term recall 68 % to 79 %**. The Tenor-style conference mic costs only ~1.6 WER points vs clean.
4. **Safety bug to fix first:** when the clipboard write fails, auto-paste still fires and would paste the *previous* clipboard contents (possibly another patient's text) into the EMR.
5. Surprise: on this card **int8_float32 benchmarked ~38 % faster than int8_float16** (same WER). Needs a longer A/B before flipping the default. distil-large-v3.5 is unusable (37 % WER).

### Setup issues on this machine (fixed or worked around)
1. **Norton Antivirus intercepts all HTTPS** (Web/Mail Shield re-signs certificates with a local root). Windows trusts that root; Python/pip/huggingface_hub do not, so `pip install` failed with CERTIFICATE_VERIFY_FAILED. Fix, scoped to the venv only: `venv1060\ssl\ca-bundle.pem` (certifi list + the Norton root, exported from the Windows store) via `venv1060\pip.ini`, plus `REQUESTS_CA_BUNDLE`/`SSL_CERT_FILE` while downloading models. Verification is never disabled. The run used `HF_HUB_OFFLINE=1`.
   - Suggestion for README_1060.md: an "antivirus / corporate HTTPS scanning" note. Alternative: `pip install truststore` (pip >= 24.2 uses the OS certificate store by default).
2. `setup_1060.bat` calls `py -3.11`. A per-user Python install without the launcher falls back to `python`, which may be the Microsoft Store stub. Worked here because the venv was created with the full interpreter path. Suggest the bat also try `%LOCALAPPDATA%\Programs\Python\Python311\python.exe`.
3. **Clipboard is denied to every process the Claude app launches**, even Windows' own `clip.exe` (OpenClipboard returns ERROR_ACCESS_DENIED; not a job object, not low integrity; no other process held the clipboard). So the **4 clipboard unit tests fail under the local Claude session only**: `test_record_stop_copies_to_clipboard`, `test_empty_result_preserves_clipboard`, `test_capture_end_auto_finalizes`, `test_phi_clipboard::test_copy_text_roundtrip`. Plain `text/plain` without the privacy formats fails the same way, so the privacy formats are not the cause. **Re-run from a normal terminal to confirm:** `venv1060\Scripts\python.exe -m pytest -q tests`.
   - **Product finding (silent loss):** when OpenClipboard fails, Qt only prints `OleSetClipboard: Failed...` to stderr and the app carries on. EMRs, Citrix and remote-desktop clients can hold the clipboard briefly, so the **dictation can silently never reach the clipboard**.
   - **Product finding (wrong-text paste, patient safety):** in the `gui` task all clipboard writes failed, yet "auto-paste fired once per non-empty result (20/20)" passed every cycle. `send_paste()` runs even when the copy failed, so it **would paste whatever was on the clipboard before, possibly text from another patient, into the EMR.** See Recommendation 1.

## Speed & memory (bench)
Cycle 1, clean `fm_diabetes_htn` dictation (~1 min, 2 chunks; short sample, so RTF differences under ~0.01 are noise). Peak VRAM is whole-card usage, including the desktop (~0.7 GB idle).

| model | compute | beam | RTF | peak VRAM | WER |
|---|---|---|---|---|---|
| large-v3-turbo (auto) | int8_float16 | 5 | 0.058 | 1979 MB | 8.5 % |
| large-v3-turbo | int8_float16 | 1 | 0.054 | 1979 MB | 8.5 % |
| large-v3-turbo | int8_float16 (forced) | 5 | 0.058 | 1979 MB | 8.5 % |
| large-v3-turbo | **int8_float32** | 5 | **0.036** | 2107 MB | 8.5 % |
| large-v3 | int8_float16 | 5 | 0.123 | 3003 MB | 7.4 % |
| distil-large-v3.5 | int8_float16 | 5 | 0.051 | 1915 MB | **37.2 %** |

- **int8_float32 was ~38 % faster than int8_float16 on the 1660 Ti**, with identical WER, the opposite of commit 49fcede's assumption. Possible causes: CTranslate2's int8_float16 kernels may not pay off on TU116 at this size, or the run order warmed things up. Needs a longer A/B (several minutes of audio, alternating order) before changing the default. Both are far faster than real time, so this is about headroom, not usability.
- Beam 1 saves only ~7 % and gave the same WER here; keep beam 5.
- large-v3 fits easily (3 GB) and is ~1 WER point better at ~2× the compute, still about 8× faster than real time. A good "max accuracy" option on this card.
- distil-large-v3.5 is unusable as configured (37 % WER, likely dropping text). Don't adopt it without investigating.

## Accuracy (eval, last full cycle)
Turbo int8_float16 beam 5, 40 synthetic dictations (SAPI voices; FM/IM/peds × 4 mic profiles). **Identical in all 7 cycles** (decoding is deterministic). WER % / term recall %:

| setting | clean | headset | conference | noisy | ALL | RTF |
|---|---|---|---|---|---|---|
| none | 6.9 / 70.8 | 7.1 / 70.8 | 7.5 / 70.8 | 9.0 / 60.0 | 7.6 / 68.1 | 0.061 |
| static | 6.3 / 76.9 | 6.5 / 76.9 | 6.6 / 73.8 | 9.3 / 60.0 | 7.2 / 71.9 | 0.063 |
| topics | 5.2 / 75.4 | 6.2 / 73.8 | 6.9 / 70.8 | 9.0 / 61.5 | 6.8 / 70.4 | 0.068 |
| **topics+fix** | **3.7 / 84.6** | **4.7 / 83.1** | **5.3 / 80.0** | **8.1 / 66.2** | **5.4 / 78.5** | 0.068 |

- topics+fix vs none: **WER down 29 % relative (7.6 to 5.4), term recall +10 points (68 to 79)**, for +11 % compute. Most of the gain comes from the spelling corrector (32 corrections). Topic prompts alone help WER but not term recall.
- Tenor-style conference audio costs only ~1.6 WER points vs clean. Noisy room is the weak spot (term recall 66 %).
- Most-missed terms (topics+fix, fictional data): **Pediacel** and **M-CHAT-R** (every profile), **crisaborole** (most), Beyfortus, ciclesonide, bilastine, MMRV, AeroChamber, betamethasone valerate, dupilumab, salbutamol (noisy). Mostly Canadian/peds brand names and hyphenated screening-tool names. SAPI mispronounces many of these, so confirm with real speech before tuning.

## Failures and what was done
- **smoke (c1): 4 clipboard tests failed.** Environment (the Claude app's process tree has no clipboard access). Not fixed. Re-run from a normal terminal.
- **long (c7): timeout after 2,308 s.** Scheduling artifact: the runner caps each task's timeout at time left + 10 min, which is less than the 60-minute dictation. Not a code failure.
- Nothing hung; no restarts; no code or threshold changes.

## Recommendations
1. **Fix before clinical use: verified copy before paste.** After `copy_text`, check that the clipboard really holds the new text (read back, or `GetClipboardSequenceNumber` changed), retrying for ~500 ms. If it still fails: **don't auto-paste**, keep the text in the window, and show a visible "Not copied: click Copy" warning. Add tests with a clipboard that rejects writes, and make the `gui` stress check assert clipboard == result before counting a paste.
2. **Compute type on Turing:** run a 5 to 10 minute A/B of int8_float16 vs int8_float32 (alternating order, several repeats). If int8_float32 is still faster, make it the default for GTX 16xx too (a name/CC rule in `hw_profile.pick_cuda_compute_type`), or default to int8_float32 everywhere, since it was never worse.
3. **Keep large-v3-turbo + beam 5 + topics+fix as the default.** Offer large-v3 as a "max accuracy" option: it fits in 3 GB and still runs 8× faster than real time on this card.
4. **Vocabulary:** check the most-missed terms with real speech (headset tomorrow). If they're still missed, add spelling variants for Pediacel / M-CHAT-R / crisaborole to the corrector's list rather than weakening its safety rules.
5. **Overnight runner:** eval is deterministic, so run it once, not every cycle. Use the time for the compute-type A/B and more `long` runs at different chunk lengths. Cap `long` so it fits before the deadline (or skip it when there's less than 60 min left). Update the heartbeat during long tasks so a "stale heartbeat" means a real hang.
6. **Setup docs:** add the antivirus/HTTPS-scanning note and a Python-launcher fallback (Environment 1 and 2).
7. Drop distil-large-v3.5 from the benchmark list unless someone wants to investigate its 37 % WER.

## On-cursor design notes (§3.4)
- **Prerequisite:** Recommendation 1 (verified copy). Live insert multiplies the number of pastes, so a silent clipboard failure would paste stale text many times per dictation.
- **Live insert mode:** at Start, record the target with `GetForegroundWindow()` (and its process ID). When a chunk finishes, paste only if the current foreground window is the same handle and not MyTranscribe. Otherwise queue the text and paste it all at Stop (or when focus returns, if that's preferred; make it a setting).
- **Spacing:** insert a leading space before every chunk except the first, and none if the chunk starts with punctuation.
- **Clipboard:** save the user's clipboard at Start, use privacy-flagged copies for each chunk, and restore the original after the final paste (best-effort; skip restoring if the user copied something in the meantime, detected by the sequence number).
- **Modifier keys:** reuse the existing "wait until Ctrl/Alt/Shift released" logic before each live paste, so a user typing a shortcut mid-dictation doesn't get Ctrl+Alt+V.
- **Chunk length:** at RTF 0.06, 10 to 15 s chunks are cheap on this GPU (~0.6 to 0.9 s each). The cost is accuracy (less context). Measure with `eval_dictation.py` at 10/15/20/30 s before changing `CHUNK_TARGET_S`. A setting ("Live: 15 s" vs "Accurate: 30 s") might be the answer.
- **Alternative to the clipboard:** typing the text with `SendInput` (unicode) avoids the clipboard entirely (no history, no stale-paste risk) but is slow for long chunks and can be mangled by EMR autocomplete. Worth prototyping for short chunks.
- **Tests:** in `tests/test_gui_med.py`, using fake foreground-window and clipboard providers: focus changes mid-dictation, MyTranscribe has focus, clipboard write failure, and the restore path.
