# Mandatory onboarding for every agent

Before any project work, read [docs/PROJECT_SOP.md](docs/PROJECT_SOP.md), then the relevant aspect's `instructions.md` and `readme.md`. These requirements apply to coordinators and delegated agents, including CPU-only research and documentation work. Give these paths to every new agent in its assignment.

Start with the SOP's onboarding checklist. Confirm the current human instruction, assigned write scope, source ownership, active jobs and latest disk checkpoint. Human instructions take precedence; an old handoff, result, schedule or SOP never grants new authorization. Existing authorized work may continue without asking again.

Focused entry points:

- Optimization: [instructions](docs/optimization/instructions.md), [how-to and plan index](docs/optimization/readme.md).
- Trial scripts: [instructions](scripts/instructions.md), [how-to](scripts/readme.md).
- Private personal evidence: `results_1060/personal_curriculum/instructions.md` and `readme.md` when present locally. This ignored folder is not expected in a fresh clone.

Read `CLAUDE.md` for development conventions and the current banner in `LOCAL_SESSION_HANDOFF.md` for historical context. Do not restart historical experiments or use obsolete hardware/default claims as current facts. Refer to the current scoped plan and source/config fingerprints before acting.
